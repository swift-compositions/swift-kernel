# swift-kernel

Use this package when you need operating system calls from Swift under one name on macOS, Linux and Windows, with typed errors and no retry or buffering added. `Kernel` resolves to the POSIX or the Windows kernel namespace for the platform you build on. Start from `Kernel.File.open(_:configuration:)` and `Kernel.File.Handle` for files, `Kernel.Event.Source.platform()` for readiness events, `Kernel.Completion.platform()` for completion-based I/O, and `Kernel.Thread.spawn` for threads. If you need calls that exist on only one platform, use swift-posix, swift-darwin, swift-linux or swift-windows directly. If you want files and directories as values, use swift-file-system.

## Laws

- `Kernel.File.open(_:configuration:)` never inspects the file system to choose a cache mode. The requirements are a fixed platform default: unknown on Darwin and Linux, a uniform 4096-byte alignment on Windows. When the requested `Kernel.File.Direct.Mode` can't be resolved against them, the file opens buffered instead of failing, and `Kernel.File.Handle.direct` says which mode it got. A created file gets the standard permissions.
- `Kernel.File.Direct.Mode.resolve(given:)` on Darwin refuses `direct` and resolves `auto` to `uncached`. On Linux and Windows it refuses `uncached`, allows `direct` only with known requirements, and resolves `auto` to `direct` when they are known and otherwise to `buffered` or a refusal, as the policy says.
- `Kernel.File.Handle` reports an interrupted read or write as `Interrupt` instead of retrying it. `Kernel.File.Handle.writeAll(from:)` keeps writing until every byte is written, treats a write of zero bytes as an I/O error, and also stops at an interruption, even if part of the buffer is already written.
- `Kernel.File.Clone.clone(from:to:behavior:)` never replaces an existing destination, not even a dangling symbolic link. With `reflinkOrCopy` any reflink failure falls back to a plain copy. On Linux the destination is created first and removed again when the clone or copy fails. Windows never reflinks.
- `Kernel.File.Copy.copy(from:to:options:)` by default refuses an existing destination, follows symbolic links, and copies permissions plus access and modification times. With `overwrite`, an existing file or link at the destination is deleted first, but a directory is refused. With `followSymlinks` off, a source link is recreated as a link.
- `Kernel.File.Move.exclusive(from:to:)` never replaces anything at the destination, not even a dangling symbolic link, and retries when interrupted.
- `Kernel.Failure.init(_:)` sorts an error code into the first matching category, checked in the order path, permission, handle, signal, blocking, space, memory, I/O, lock. A code that matches none gives nil.
- A `Kernel.Event.Source` takes ownership of each registered descriptor and gives it an ID, counting up from 1. Every interest is one-shot: once an event is delivered, the kernel reports nothing more for it until `Kernel.Event.Source.arm(id:interest:)` is called again. Interests armed since the last delivery add up, and those a delivered event didn't cover are re-armed during the poll.
- `Kernel.Event.Source.poll(deadline:into:)` asks the kernel for no more events than the buffer holds, so the rest stay pending for the next poll. It drops events for IDs already deregistered and returns 0 when interrupted.
- `Kernel.Event.Source.deregister(id:)` does nothing for an unknown ID and ignores a descriptor the kernel already forgot. `Kernel.Event.Source.modify(id:interest:)` and `Kernel.Event.Source.arm(id:interest:)` fail for an unknown ID, and a failed modify keeps the previous interest.
- On Darwin, end of file is reported as a hangup together with a read or write hangup for the filter that saw it. Linux reports a read hangup but never a write hangup.
- `Kernel.Completion.platform()` is io_uring on Linux and fails on every other platform. `Kernel.Completion.submit(_:target:)` only queues, and fails when the queue is full. Nothing reaches the kernel until `Kernel.Completion.flush()`, which does not wait for completions. A read or write without an offset uses the file's current position.
- A negative `Kernel.Completion.Event.Result` is the negated POSIX error code.
- `Kernel.Thread.trap` works like `Kernel.Thread.spawn` but traps instead of throwing when the thread can't be created. `Kernel.Thread.Handle.joinChecked()` traps when called from the thread being joined. A `Kernel.Thread.Handle.Reference` must be joined exactly once and traps when joined twice or released unjoined.
- `Kernel.Thread.Affinity.apply(_:)` pins only on Linux and Windows. Elsewhere any affinity except `any` fails as unsupported. A NUMA node that the CPU doesn't report fails as an invalid node.
- `Kernel.Lock.Acquire.timeout(_:)` turns the duration into a deadline on the continuous clock at the moment it is called.
- `Terminal.Mode.Raw.Token.restore()` only restores once and does nothing after that. A token that is dropped without being restored leaves the terminal in raw mode.
